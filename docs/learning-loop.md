# StudyBridge 课程学习闭环

## 学生选择如何开始

课程聊天顶部常驻“学习清单 · 练习”。入口提供学习清单、整理资料、练习记录；所有自动提示关闭后仍然可用。通用聊天不显示课程学习清单。

学习面板沿用工作区的轻量文字导航、细分隔线、收敛的字体和主题色。每个主题突出练习入口，将“回看资料”、复习日程和历史作答作为次要操作；“自己添加主题”和编辑表单按需展开。面板顶部显示当前课程，底部提供自动建议开关和私有状态。改变视图回到内容起点，同一视图刷新保留滚动位置和已展开的编辑区域。

应用内学习、设置、日程管理、图片预览和邀请码确认弹窗共用 860 × 576 CSS 像素的固定外框；较小屏幕按可用视口收窄、缩短。切换栏目、加载内容、展开表单或显示错误都不改变外框尺寸。标题、关闭按钮和底部操作保留在外框内，中间内容独立上下滚动；设置导航独立滚动。无主题、无课程资料或无练习记录时，居中显示对应提示并保留留白。尺寸由 `public/dialog-layout.css` 统一管理。

在有可读课程资料而尚无主题、上传资料后、课程讲解结束或当前课程有待复习主题时，可以弹出一张不抢焦点的学习建议卡。输入后至少等待五秒，生成回复或后台解题时继续等待；页面隐藏或离开当前学习空间后不弹出。建议不自动调用 AI、发送消息、创建日程或打开学习弹窗。

- “我想试试”：学生主动打开学习入口。
- 关闭：保留自主入口，本次浏览会话不再重复提示；浏览器另有十分钟的显示间隔。
- “稍后再说”：该课程暂停自动建议一天，保存到账号。
- “关闭自动提示”：关闭该课程的自动建议，保存到账号；可在学习入口底部重新打开。

这些是应用内建议，不是系统通知或离线推送。选择学习、作答、查看答案、安排时间和发送 AI 讲解请求均由学生决定。课程、页面或账号切换时，旧请求不能把弹窗或结果显示在新位置。

## 五个环节

1. **资料 → 学习清单。** 学生选择 1–6 份本课程资料，生成 1–12 个主题草稿。可改名、取消勾选、确认或放弃；确认前不会修改正式主题。较长资料抽样读取开头、中间、末尾，页面明确说明不能保证完整覆盖，也不能据此推断考试范围。没有可读文字的扫描件须先补充文字。每门课最多 80 个主题。也可以直接添加自己的主题，再用课程资料中的 5–300 字符原文关联出处。
2. **主题 → 学习与短测。** 查看可核对的资料片段，显示真实 PDF 物理页码或提取文字位置。选择 AI 讲解会把请求追加到现有聊天草稿，由学生自行发送。练习按所选主题和资料生成三道有四个选项的单选题，涵盖概念辨析、解释和应用。AI 调用保留已有学习语言偏好、最长一分钟，使用私有非流式请求。
3. **作答 → 留下反馈。** 提交前不返回答案编号和解析；明确选择“先看答案与讲解”后可提前查看，本次永久记为辅助练习。提交必须回答全部三题，服务端对照保存的答案计分，忽略客户端声称的分数和帮助状态。保存题目、答案、错选原因、正确解释和出处。刷新后可从最近 24 次练习恢复题目或查看反馈；未提交的选项保留于当前页面会话，刷新后需重新选择。
4. **薄弱点 → 确认复习时间。** 每个主题都能选择“安排复习”，建议 15 分钟，允许选择 5–120 分钟和未来的本地时间。显示时区，点击确认才保存，和已知日程冲突时要求换时间。新安排出现在原有日历，带有“开始复习”入口。建议检查不是对所有并发日历修改的排他预订；不创建一整周的强制任务。
5. **复习 → 新题与更新安排。** 日程入口直接为原主题创建新题，把既往错题作为出题重点和避免重复的参考。提交后完成关联日程，并更新主题记录。全对且未看答案记为“本次独立答对”，建议三天后再练；连续独立全对建议七天。其他结果建议一天后再练。这些是可调整的初始产品规则，不是能力百分比或考试成绩预测。阅读、聊天、手动完成日程都不会产生掌握证据。

当前版本的短测是三道单选题，不包括自由作答自动批改，也不保证 AI 出题与答案的语义正确性。新题不接受完全相同的题干；不同措辞的语义重复仍需实际使用检验。社区保持可选，学习资料和错题不会自动公开。

## 数据与接口

`/api/courses/:courseId/learning-loop` 接入现有账号和课程权限。GET 返回主题、待确认草稿、最近练习摘要、建议偏好和可选资料。子接口包括：

| 接口 | 行为 |
| --- | --- |
| POST `extract` | 从选中资料生成草稿，提交当前 `version` |
| POST `topics` | 确认/放弃草稿、添加/改名/删除主题或关联出处；要求当前 `version` |
| POST `quiz` | 按 `topicId` 和客户端唯一 `requestId` 保存并返回短测，可携带复习 `taskId` |
| GET `quiz?id=...` | 恢复当前课程内的练习 |
| POST `submit` | 记录完整答案；重复提交保留第一次结果 |
| POST `help` | 永久标记辅助练习并返回解析 |
| POST `plan` | 确认时间、时长、时区及 `requestId` 后保存课程日程 |
| POST `preferences` | 设置 `prompts`，或以 `snooze: true` 暂停一天 |
| GET `source?topicId=...` | 读取仍然有效的课程出处与周边片段 |

所有响应私有且不缓存。出处的文件、引用原文和页码范围在服务器校验；课程资料变更后，旧题不能继续计入主题表现。需重新关联资料，再生成新题。已提交的历史反馈仍然可以查看。

本地数据库新增 `learningStates`、`learningQuizzes`；DynamoDB 在账号课程前缀下新增 `LEARNING` 和 `QUIZ#id` 记录。无需迁移历史数据或修改 AWS 权限。主题、练习结果、关联任务完成状态在一个本地写入或 DynamoDB 条件事务中提交；跨设备过期主题编辑返回冲突。事务同时检查课程存在和相关资料版本，防止晚到结果恢复已删除的课程或引用旧资料。删除课程一并清理学习记录；删除单个主题保留历史练习。

## 验证

本地和模拟 DynamoDB 测试覆盖草稿确认、可核对出处、答案隐藏、真实计分、辅助标记、错题保留、间隔建议、幂等重试、条件事务、日程关联与完成、资料更新、账号和课程隔离。HTTP 测试覆盖鉴权、重启恢复、建议偏好和课程删除。浏览器使用隔离账号、临时数据库和模拟 AI，验证自主入口、自动卡片不抢焦点、关闭提示后的继续学习、手机布局、英语界面和日程回流。

不产生线上测试数据。真实课程出题质量和线上 AWS 部署需分别验证；任务分支推送不会触发 main 的部署工作流。
