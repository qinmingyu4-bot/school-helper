# 整套题后台解答

课程对话上传包含至少六道连续编号题目的文件时，网页提交后台任务；明确要求解答整套扫描 PDF/题图时，先识别题目。模拟出题、作业要求拆解、预习、cheatsheet、提示模式、单题/单小问和总结翻译请求继续使用原流程。普通聊天仍然流式回答。后台任务保留当前学习偏好和学习模式，每个小问包含方法、过程与答案。

系统先保存原题及题目清单，一次补充中英检索词和题目依赖，再按题检索当前课程共享资料及当前对话的附件。其他用户、课程、对话附件不参与检索。五道独立题为一组，证明题/较多小问单独处理；依赖题等待前组完成。全站同时最多两个 AI 识别/作答批次，本地数据库和 DynamoDB 均使用持久化条件租约。**不限制 PDF 解析并发，不新增上传限制**；现有文件大小/API 请求大小限制保留。

每组返回结构化结果，服务端核对原题号、全部已识别小问和每题允许引用的资料编号，保留有效答案，仅重试失败题。出处由服务器根据真实文件、版本、PDF 物理页或提取文本行/字符范围生成。无法识别的图或小问单独标明，不能计入完成数。资料在处理期间被编辑或删除时，不接受旧版本产生的新结果；保留已完成内容，并提示重新提交未完成题。出处位置可校验，答案语义正确性仍需单独质量验证。

页面按原题顺序显示已经完成的批次及“已完成 x/y 题”。刷新、离开再返回及进程重启后恢复；停止保留进度，重试继续未完成的题组。断开浏览器连接不会停止已接受任务。处理期间同一对话接受同一任务的重发，其他整套题可在停止当前任务后提交；普通文件上传不经过这个队列。识别不到编号的扫描件依赖视觉识别，不能保证把无法辨认的原题全部识别出来。

## 存储与索引

- `lib/material-files.js` 将材料放在本地数据库同目录的私有 `material-files/`。主 JSON 仅保留材料的作用域、ID、哈希和字节数；原件、检索索引、任务输入、计划和分组结果均在磁盘。最终对话正文仍按原聊天机制保存。
- 文件以用户/课程、材料 ID、内容哈希定位，写入后才发布引用；读取校验哈希及大小。旧 `.value` 材料仍可读取，启动后逐项安全整理原件，不清空任何账号或课程数据。DynamoDB 保留已有分块材料存储，新增任务元数据及全局队列/租约记录，使用已有事务权限。
- 上传及修改课程文件后异步建立分段索引，不阻塞上传确认。索引版本包含文字、标题及页码，旧版本在新索引发布后清理。单批作答只载入一次各资料索引；常驻缓存只保留近期选中片段，默认上限 4 MB、有效期一分钟。
- 附件文字另存为派生材料，后台检索无需反复加载原件。需要题图或讲义图表时才读取原件，同批合并需要的 PDF 页面并保留原页码映射。整套题各组共享同一份原件，选页结果只在请求期间存在。

## 接口

`POST /api/courses/:courseId/chat` 支持 `background: true` 和客户端唯一 `requestId`（8–100 位字母数字、下划线/连字符）；命中整套题时返回 `202 {job,message}`，其他情况保留已有 SSE/JSON 行为。相同请求标识及内容幂等；更换内容必须使用新标识。

`GET /api/courses/:courseId/study-jobs?conversationId=default` 恢复该对话最近十二项及全部未完成任务；`GET .../study-jobs/:id` 读取进度；`POST .../study-jobs/:id` 的 `{action:"cancel"}` / `{action:"retry"}` 停止/重试。所有接口验证课程和对话归属。网页只在当前学习对话有进行中任务时每 1.5 秒刷新进度，账号/课程切换丢弃旧请求结果。

状态包括 accepting、queued、planning、running、completed、partial、needs_input、failed 和 canceled。任务记录及结果在原数据库位置持久化，服务正常停止会撤回执行中的工作；意外退出后租约过期可恢复。每个批次默认两分钟截止、最多两次自动尝试；人工重试保留已完成题，不重做整套。首次结果、开始、完成时间可从任务 `timings` 读取。

## 验证与后续实测

自动化使用七份课程资料和二十道两小问题，验证分批结果、两个服务共享全站并发限制、断点恢复、失败题独立重试、不可读题、资料更新期间的旧引用拒绝、跨账号/课程/对话隔离、私有文件备份及旧代码兼容恢复。HTTP 测试使用虚构 AI 服务，不产生外部调用或线上数据。

模型调用仍是主要耗时，不能用模拟响应时间承诺真实提速比例。发布前应以同一套真实“七份资料＋二十道题”记录首次答案时间、总完成时间、漏题/漏小问、引用准确性、模型费用、峰值内存和队列等待，再决定是否调整组大小或扩容。没有完成生产压力测试前，不据此承诺同时在线人数。
