# StudyBridge 单机 SQLite WAL 扩容预案

**状态：备用。** 2026-11-23 核对的 Lightsail JSON 数据库约 2.8 MiB。
在 Mac 上用同等大小的合成数据，StudyBridge 现有 JSON 保存代码完成 10 个同时到达的
日程小更新约需 27 毫秒，SQLite WAL 原型约 0.38 毫秒。数据库为 64 MiB 时，同样测试
约需 608 毫秒和 0.30 毫秒。数值为整批完成时间的中位数。线上核对只测了文件大小，
保存耗时来自本机模拟。线上目前继续使用 JSON。

## 何时启动

- 先收集线上数据库体积、保存操作的写入排队和落盘耗时，再把这些数据与成绩、日程、
  笔记的接口耗时对照。优先使用只读检查或已有指标，选择有代表性的高峰期。
- 当写入持续排队，且占用户可感知延迟的重要部分时，立项迁移演练。数据库文件大小用于
  观察增长趋势，实际保存表现决定是否切换。页面刷新单独分段计时。
- 目标是单台 Lightsail 内按记录更新，启用 SQLite WAL。若目标变为多台服务器共享写入，
  应重新评估数据库选型。上线前检查实际 SQLite 运行时包含 WAL 修复。
  [SQLite WAL 文档](https://sqlite.org/wal.html)

## 迁移演练与验收

1. 在隔离环境恢复一份经过校验的备份，包括数据库和配套的材料、作品等私有文件。
   检查新旧存储之间的记录数、ID、账户归属和附件引用，覆盖历史字段与未知记录。
2. 用同一份备份逐项验证登录与账号隔离、课程资料和原始附件、聊天与草稿、成绩、
   日程和笔记、Office 项目、会员与额度。并发提交后重启，验证最新数据仍能读出。
   对照 JSON 的典型耗时及较慢请求的耗时，确认最常用的读写路径通过回归。
3. 验证 SQLite 一致性备份及恢复，包含外置文件。使用 SQLite 在线备份接口或
   `VACUUM INTO` 生成一致的数据库快照。[SQLite 备份文档](https://sqlite.org/backup.html)
4. 完成一次正向迁移和一次回退演练，并记录耗时。只有演练通过、实测收益明确并获
   上线授权后，才在短暂停写期间迁移最新备份，完成核对后再开放写入。

## 回退边界

保持一份校验通过的切换前备份。新库接受用户写入前，出错可恢复原应用与原 JSON。
开放写入后，先暂停写入并为当前 SQLite 与配套文件制作一致快照，再通过已演练的
转换流程把最新数据迁回 JSON。逐项校验通过后恢复旧版服务。迁移实现必须验证
这条回退路径能保留切换后新增及编辑的数据。
