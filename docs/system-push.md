# 日程系统推送

在「日程 → 系统提醒设置」或「设置 → 课程与提醒」开启此设备的系统推送。主动授权后可选择到时间、提前 5/15/30 分钟、1 小时或 1 天提醒，默认提前 15 分钟。可发送测试通知、关闭当前设备或刷新状态。通知使用通用文案，不在锁屏展示课程、作业标题或备注；点击后打开日程对应日期，原有网页已打开时保留聊天草稿。

本次不提供安装、添加到主屏幕引导、邮件或原生 App 推送。不支持网页推送的浏览器显示不可用状态；iPhone 普通浏览器标签页不支持此功能。已支持推送的 iOS 主屏幕网页仍可使用，未来原生 iOS App 需要单独接入 APNs/本地通知，不能直接复用网页订阅。

## 配置与上线

需要 HTTPS、Node.js 常驻进程和现有数据库；无需新增表或迁移已有日程。部署仍须项目所有者授权，在任务分支准备不会启用生产通知。

在服务器私有环境文件上运行一次：

```sh
node scripts/configure-web-push.js /private/path/.env mailto:YOUR_REAL_CONTACT_ADDRESS
```

脚本生成持久 VAPID 公私钥和有效联系地址，保留其他配置、拒绝覆盖已有密钥，不打印私钥。设置 `WEB_PUSH_PUBLIC_KEY`、`WEB_PUSH_PRIVATE_KEY`、`WEB_PUSH_SUBJECT` 后重启应用。不要将环境文件或密钥提交 Git。轮换密钥会要求设备重新订阅。`WEB_PUSH_WORKER_DISABLED=true` 仅供隔离测试关闭后台发送。服务器需能向浏览器的 Apple、Google、Mozilla 或 Windows 推送服务发起 HTTPS 请求。

## 后台与数据

服务器每 30 秒分页处理已订阅设备，读取最新日程、跳过完成/删除事项，按保存的 UTC 或学校时区计算时间；不依赖网页常驻。每设备支持一个提前量，日程各次发生独立提醒。改期按新时间处理；改标题不会重复提醒。授权前已到提醒时间的旧事项不补发。短暂中断重试最多补发近 5 分钟的提醒，超过窗口跳过，防止恢复后大量过时通知。推送 TTL 不超过剩余补发窗口。

设备订阅及去重记录保存在现有本地私有数据库或 DynamoDB `SCHEDULE_PUSH` 分区；订阅端点和设备密钥视为私密数据，不记录到日志。DynamoDB 条件写与两分钟租约防止多个实例并发发送；本地文件数据库沿用单进程运行要求。临时失败一分钟后重试，404/410 删除失效订阅。持久去重历史保留七天、最多 1000 条。推送服务接受后、保存结果前进程崩溃仍可能重复，使用相同通知 tag 合并；不承诺精确一次送达。

订阅绑定当前登录会话，退出登录、会话到期、密码变更或账号删除后停止发送，并在后台清理。重新登录后需重新开启。其他设备仍按各自会话运行。每次发送前校验会话；接收时再核对当前账号，避免排队消息显示在另一个账号中。授权、更改与测试接口需登录、会话 CSRF 和账号一致性校验，外发仅允许已知浏览器推送服务。测试通知每设备限 30 秒一次。

实际通知显示依赖网络、浏览器进程策略、系统权限、勿扰和省电设置，不保证响铃、亮屏或精确到秒。服务器只能确认推送服务接受，不能据此认定用户已看到；用户应使用真实设备的测试通知确认。部署后须在 Android、桌面浏览器及可用的 iOS 主屏幕网页实测：页面关闭/锁屏、点击跳转、拒绝授权、关闭推送、改期/完成/删除和退出登录。普通 iPhone 标签页应显示不支持，且不出现安装引导。
